# Prioritization and Scope

Identify the desired outcome and competing work. Ask what is essential for a useful first result, what can wait, consequential dependencies, deadlines with reasons, and what should explicitly stay out. Explore tradeoffs with concrete scenarios rather than forcing numerical scores.

Useful probes: “If we could ship only one of these, which unlocks the most value?” “What would make a smaller first version unusable?” “Which deadline is fixed, and what drives it?” Distinguish user commitments from suggested sequencing.

Close with agreed first scope, deferred work, rationale, dependencies, and success criteria. Do not convert optional suggestions into commitments, create a backlog file automatically, or expand implementation beyond the selected scope.
