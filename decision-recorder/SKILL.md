# Decision Recorder

Use the repository’s decision template, numbering, and index if present. Capture one decision with its status, context and constraints, viable options actually considered, selected approach and rationale, and concrete benefits, costs, or follow-ups. Cite the evidence or discussion that supports it; do not invent alternatives or infer consensus. Use proposed status for unsettled choices.

When a decision changes, preserve the historical rationale and link the replacement and predecessor according to repo convention. Add an index entry if the repository maintains one. Keep routine implementation details in code or a handoff. A question about an existing decision calls for reading its record; create or revise a record when requested.
